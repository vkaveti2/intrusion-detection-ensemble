    * STRUGGLE & RESOLUTION — Feature Dimension Discrepancy (78 vs 77 features):
      Literature and raw CIC-IDS2017 documentation often cite 78 numerical features.
      However, the raw data contains an exact duplicate column: "Fwd Header Length.1"
      and "Fwd Header Length". In train_models.py, "Fwd Header Length.1" and "Label"
      were dropped, resulting in strictly 77 numerical features. Initial environment
      definitions and manual scripts assumed 78 features, causing shape mismatch
      exceptions. Standardized all downstream models and environments to FEATURE_DIM = 77.

[2026-10-08 14:22 – 15:53] Initial DDQN Implementation & Flat Evasion Bug
    - Initial attempt to train DDQN agent against base models using train_ensemble_ddqn.py
      and early ids_env.py.
    - Convergence logs (convergence_ensemble_majority_black.json) showed an evasion
      rate flat-lined at exactly 100.0% across all 100 episodes from step 1.

    * STRUGGLE & RESOLUTION — The "Zero-Feature" / Sparse Flow Simulation Bug:
      Audited the ensemble across all 1,250 possible discrete action combinations:
      every single action was classified as "normal" (benign) with 100% confidence.
      Root Cause: Early _simulate_probe only populated 9 features (port, delay, etc.),
      leaving all remaining 68 statistical flow features (packet counts, packet length
      variances, flow packets/s, Init_Win_bytes_forward) as 0.0. In CIC-IDS2017,
      an empty/silent flow is learned as idle background traffic. The RL agent
      received free +1.0 evasion rewards without needing to explore or learn.
      Identified the necessity of grounding probe simulations in real network flows.

    * STRUGGLE & RESOLUTION — Stable-Baselines3 DQN vs True Double DQN:
      Audited Stable-Baselines3's DQN implementation against the thesis methodology.
      SB3's DQN implements classic Nature DQN (Mnih et al., 2015) using
      max_{a'} Q_target(s', a'), which suffers from value overestimation. The thesis
      explicitly specifies Double DQN (Van Hasselt et al., 2015). A custom DoubleDQN
      subclass was architected to decouple action selection (argmax Q_online) from
      target evaluation (Q_target(s', a*)) to guarantee academic rigor.

[2026-10-14 16:30] Scientific Diagnosis of Run v1 — INVALID & UNUSABLE FOR THESIS
    A thorough audit revealed that Run v1 was fundamentally flawed and ungrounded:

    1. Untrained Baseline Artifact (No Real Learning):
       Testing a purely random, untrained policy produced 93.9% evasion on majority
       and 99.0% on unanimous. The trained DDQN agent only added 1–6% evasion.
       No meaningful adversarial learning had taken place.
    2. Hypersensitive Artificial Decision Boundaries:
       The pure PortScan median vector was correctly flagged by all 3 detectors (~100%
       confidence). However, linearly shifting the vector by just 3% toward benign
       flipped XGBoost to classify it as benign; shifting by 10% flipped Random Forest.
       Because the heuristic blend formula gave large stealth weights to delay, virtually
       every agent action blended >= 3% toward benign, trivially fooling the models.
    3. Physical Impossibility of Delay on Single-Flow Features:
       In CICFlowMeter, statistical features are computed across packets *within a single
       flow* (flow duration, packet inter-arrival times, flow rates). Inter-probe delay
       is the pause *between* separate single-packet scan flows. In a real network,
       waiting 5 seconds between SYN probes does NOT alter the packet statistics of an
       individual SYN flow. The simulator artificially corrupted flow features with delay.
    4. Observation Normalization Failure:
       White-box agents received raw, unscaled feature observations (values ranging
       from 0 to 10^7), severely destabilizing neural network gradient updates.
    5. Inverted Threat Model (Unanimous Voting):
       "Unanimous voting" (requiring all 3 detectors to agree to flag an attack) was
       treated as a strong defense, when in reality requiring unanimous consensus is
       the most permissive defense possible for an attacker (easiest to evade).
       "Any voting" (logical OR: 1 of 3 flags) is the true strict defensive baseline.

    * ACTION TAKEN: Archived all v1 models, checkpoints, and convergence logs to
      results_ddqn_v1_blend_sim_archive/ (2026-10-14 17:29) to prevent pollution of thesis.

[2026-10-14 17:27] Pre-Flight Smoke Test & Key Vulnerability Discovery
    * STRUGGLE & DISCOVERY — The "Payload Shortcut" Vulnerability:
      Tested detectors across discrete payload sizes (0 to 512 bytes):
        * 0-byte payload: Evasion rate = 0.0% to 14.7% (models catch scans reliably).
        * 64+ bytes payload: Evasion rate instantly jumps to 60.0% – 100.0%!
      CRITICAL FINDING: All three detectors learned a severe dataset-specific shortcut.
      In CIC-IDS2017, all PortScan flows had 0–2 byte payloads, while benign flows had
      substantive payloads. All three classifiers learned that "payload > 0 => benign traffic".
      Ensembling cannot mitigate this vulnerability because all ensemble members were
      trained on the same underlying dataset and share the exact same blind spot.

    * CRITICAL THESIS FINDING — The "Ensemble Collapse" Phenomenon:
      Under real-flow probe evaluations, detector decisions form a strict hierarchy:
      XGBoost-flagged subset of RF-flagged subset of CNN-flagged.
      Because of this nested structure, multi-model voting rules collapse entirely:
        * unanimous == xgboost (identical convergence curve and decisions)
        * majority  == rf      (identical convergence curve and decisions)
        * weighted  == rf      (identical convergence curve and decisions)
        * any       == cnn     (identical convergence curve and decisions)
      Voting ensembles provide ZERO emergent defensive benefit against payload-padding
      attacks beyond the capability of their individual member models.
